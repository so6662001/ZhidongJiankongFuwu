# 企业微信 / 邮件 真实投递联调指南

> 集成层的通知逻辑（路由、兜底、升级、回执）已实现并实测；**真实投递需要你提供凭据**。
> 本文说明如何配置真实渠道并联调验证。沙箱内无凭据，邮件已用本地 SMTP 捕获器验证、企业微信结构已验证。

## 通知渠道与优先级

`NOTIFY_MODE=failover`（默认）下顺序：
1. **企业微信应用消息**（精准@人，需 corpid/agentid/secret + 接收人 userid）
2. 应用消息未配置/失败 → **企业微信群机器人**（群播，需 robot webhook）
3. 仍未成功 → **邮件兜底**（需 SMTP）

`NOTIFY_MODE=all` 则各已配置渠道都发。

## A. 企业微信群机器人（最易，推荐先用它联调）

1. 在企业微信群「添加群机器人」，复制 Webhook 地址（含 `key=`）。
2. 配置 `WECOM_ROBOT_WEBHOOK=https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxxx`。
3. 联调：
   ```bash
   curl -X POST http://<host>:8080/api/v1/notify/test -H 'X-Api-Key: <key>' \
     -H 'Content-Type: application/json' -d '{"serviceName":"order-service"}'
   ```
   群里应收到 markdown 告警卡片；`/api/v1/alerts/{id}` 的 notifyLogs 有 `wecom_robot` 回执。

## B. 企业微信应用消息（精准@人）

1. 企业微信管理后台 → 应用管理 → 自建应用，获取 `corpid`、应用 `agentid`、应用 `secret`。
2. 配置：`WECOM_CORPID`、`WECOM_AGENTID`、`WECOM_SECRET`（生产用 Secrets 注入，勿明文）。
3. 在「服务负责人」配置该服务的 `wecomUserids`（企业微信成员 userid），或排班 `oncall`。
4. 联调：同上 `/notify/test`，对应负责人会被精准推送 textcard，可点击跳详情。
   - access_token 自动缓存于 Redis（失效自动刷新重试）。

## C. 邮件 SMTP

1. 配置：`MAIL_HOST`、`MAIL_PORT`、`MAIL_USERNAME`、`MAIL_PASSWORD`（企业邮箱通常用授权码）、`MAIL_SSL=true`。
2. 在「服务负责人」配置 `emailList`。
3. 联调：`/notify/test` 带 `{"emails":"you@company.com"}`，收件箱应收到 HTML 告警邮件。
4. 本地无账号时，可用 `python3 -m aiosmtpd -n -l 127.0.0.1:1025` + `MAIL_HOST=127.0.0.1 MAIL_PORT=1025 MAIL_SSL=false MAIL_AUTH=false` 验证发信链路（本项目已用此方式实测通过）。

## 在 Cursor Cloud Agent 中提供凭据

把以下变量加到 **Cursor Dashboard → Cloud Agents → Secrets**（用户/团队/仓库级），新 Agent VM 会以环境变量注入：

```
WECOM_ROBOT_WEBHOOK=...
WECOM_CORPID=...  WECOM_AGENTID=...  WECOM_SECRET=...
MAIL_HOST=...  MAIL_PORT=465  MAIL_USERNAME=...  MAIL_PASSWORD=...  MAIL_SSL=true
```

配置后即可用上述 `/notify/test` 与真实告警链路完成端到端投递验证。
