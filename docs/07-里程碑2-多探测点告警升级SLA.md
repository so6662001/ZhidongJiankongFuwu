# 里程碑 2：多探测点、告警升级、SLA 大盘、通知兜底

> 在 MVP（阶段 0~6）基础上扩展。代码见 `monitor-integration/`，部署见 `deploy/README.md`。

## 1. 通知兜底切换（failover）

- 配置 `NOTIFY_MODE`：
  - `failover`（默认）：**企业微信优先**，企业微信不可用/发送失败时**自动兜底邮件**。
  - `all`：所有已配置渠道都发。
- 每次发送均写 `notify_log` 回执；网关返回各渠道成功与否用于决策兜底。
- 联调测试：`POST /api/v1/notify/test`（带 `X-Api-Key`）
  ```bash
  curl -X POST http://localhost:8080/api/v1/notify/test -H 'X-Api-Key: <key>' \
    -H 'Content-Type: application/json' \
    -d '{"emails":"ops@company.com","wecomUserids":"zhangsan"}'
  # 或按服务负责人路由： {"serviceName":"order-service"}
  ```
- 真实投递验证：邮件可用本地 SMTP 捕获器（如 `python3 -m aiosmtpd -n -l 127.0.0.1:1025`）
  配合 `MAIL_HOST=127.0.0.1 MAIL_PORT=1025 MAIL_SSL=false MAIL_AUTH=false` 验证；企业微信需真实 corpid/agentid/secret。

## 2. 告警升级（escalation）

- 定时任务（`EscalationScheduler`）按 `ESCALATE_SCAN_INTERVAL_MS` 周期扫描 **firing 且持续超过 `ESCALATE_AFTER_SECONDS`** 的告警。
- 触发升级：向「升级接收人（`ESCALATE_WECOM_USERIDS`/`ESCALATE_EMAIL_LIST`）+ 该服务负责人」再发一次（标题带「告警升级」）。
- 升级后置 `alert.escalated=1`、`escalated_at`，避免重复升级。
- `ESCALATE_AFTER_SECONDS<=0` 关闭升级。

## 3. SLA / 可用率大盘

- 计算：`GET /api/v1/stats/sla?serviceName=&hours=24`。按监控将告警 firing 时段**合并区间**求故障时长，
  `可用率 = (窗口 - 故障时长) / 窗口`，返回每监控可用率与最差可用率。
- 大盘页面：`http://<host>:8080/dashboard.html`（静态页，免鉴权访问；调用 API 时在页面输入 `X-Api-Key`）。
  展示当前告警数、今日告警、最差可用率、各监控 SLA、最近告警。
- 说明：SLA 基于告警记录估算；如需更精细的探测级可用率，可结合 HertzBeat 在 VictoriaMetrics 的历史指标。

## 4. 多探测点 / 多地域

HertzBeat 支持**多采集器（collector）集群**实现多探测点、多地域、内外网隔离探测。

### 4.1 部署额外采集器

用 HertzBeat collector 镜像，连接到主节点（manager）的 1158 端口：

```yaml
  hertzbeat-collector-beijing:
    image: apache/hertzbeat-collector:latest
    restart: unless-stopped
    environment:
      IDENTITY: collector-beijing          # 采集器唯一标识
      MANAGER_HOST: hertzbeat               # 主节点地址
      MANAGER_PORT: 1158
    depends_on:
      - hertzbeat
```

在不同地域/网络分别部署采集器（如 `collector-beijing`、`collector-shanghai`、`collector-internal`）。

### 4.2 把监控指定到采集器（探测点）

导入时通过 `collector` 指定采集器（不填则系统自动调度）：

```bash
# OpenAPI 导入指定采集器
curl -X POST http://localhost:8080/api/v1/provision/import-openapi -H 'X-Api-Key: <key>' \
  -H 'Content-Type: application/json' \
  -d '{"openapiUrl":"https://svc/v3/api-docs","dryRun":false,"collector":"collector-beijing"}'

# 清单导入：整体 defaultCollector 或单条 item.collector
curl -X POST http://localhost:8080/api/v1/provision/import -H 'X-Api-Key: <key>' \
  -H 'Content-Type: application/json' \
  -d '{"defaultCollector":"collector-internal","items":[{"url":"https://10.0.0.5/health"}]}'
```

> 同一接口若要「多点拨测、多数失败才告警」，可在 HertzBeat 中对该接口在不同采集器各建一个监控，
> 或使用 HertzBeat 的采集器分组能力（按版本）。本集成层已支持按 `collector` 维度纳管。

## 5. 相关环境变量（详见 `deploy/README.md`）

| 变量 | 说明 |
| --- | --- |
| `NOTIFY_MODE` | failover / all |
| `ESCALATE_AFTER_SECONDS` | 升级阈值秒数（<=0 关闭） |
| `ESCALATE_WECOM_USERIDS` / `ESCALATE_EMAIL_LIST` | 升级额外接收人 |
| `MAIL_SSL` / `MAIL_AUTH` | 邮件 SSL/认证开关（本地 SMTP 联调置 false） |
